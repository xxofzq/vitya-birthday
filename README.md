# Поздравление для Вити

Готовый статический сайт на HTML, CSS и JavaScript. Сборка, backend и установка зависимостей не нужны. Первый экран сохранён; второй содержит пробковую доску, три исходные фотографии, три поздравления и просмотр фото крупным планом.

## Файлы

- `dist/index.html` — первый экран и разметка поздравления.
- `dist/app.js` — конверт, печать текста, переход между экранами и просмотр фото.
- `dist/board.css` — стили доски, фотографий, записок и мобильной версии.
- `dist/favicon.svg` — значок сайта.
- `dist/assets/images/photo-1.jpg`, `photo-2.jpg`, `photo-3.jpg` — предоставленные фотографии без изменений.
- `.github/workflows/pages.yml` — публикация папки `dist` через GitHub Pages.

Все пути относительные. Навигация использует `#next` и `#letter` внутри одной страницы. Сайт подходит и для адреса с именем репозитория в пути, и для своего домена. В архив не включены служебные данные Sites, история Git и временные проверки.

## Опубликовать на GitHub Pages

1. В своём аккаунте `xxofzq` создай **публичный пустой** репозиторий `vitya-birthday`. Не добавляй README, лицензию или `.gitignore` при создании.
2. Распакуй архив. Открой терминал в папке `vitya-birthday-site`, где лежат `README.md` и папка `dist`.
3. Выполни:

```bash
git init
git add .
git commit -m "Birthday website"
git branch -M main
git remote add origin https://github.com/xxofzq/vitya-birthday.git
git push -u origin main
```

Для HTTPS GitHub может запросить авторизацию через менеджер учётных данных или personal access token. Обычный пароль аккаунта не используется для Git push. Не размещай токен в файлах проекта или в команде remote.

4. В репозитории открой **Settings → Pages → Build and deployment → Source → GitHub Actions**. Не выбирай публикацию папки `dist` через ветку: GitHub Pages предлагает для этого только корень или `docs`, а этот проект сохраняет существующую папку `dist`.
5. Открой **Actions → Publish birthday website**. Если первый запуск не успел завершиться успешно до включения Pages, нажми **Re-run all jobs**. Можно также нажать **Run workflow**, выбрав ветку `main`.
6. Дождись зелёного результата. Рабочую ссылку возьми из **Settings → Pages → Visit site** или из deployment `github-pages`. Открой её в инкогнито и проверь конверт, кнопку, все три фото и их увеличение.

GitHub Pages публикует сайт в интернете: по обычной ссылке его можно открыть без регистрации. Настройка Actions не требует добавления пользовательских API-ключей или секретов.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## Без терминала

В пустом репозитории выбери **Add file → Upload files** и загрузи содержимое распакованной папки: `README.md` и всю папку `dist`. Файл workflow добавь отдельно через **Add file → Create new file**: имя `.github/workflows/pages.yml`, содержимое скопируй из такого же файла в архиве. Сохрани изменения в `main`. Затем выбери **Settings → Pages → Source → GitHub Actions** и запусти workflow.

## Посмотреть локально

```bash
python3 -m http.server 8000 --directory dist
```

Открой `http://localhost:8000`. Файлы также работают без сборки при открытии `dist/index.html` в современном браузере.

## Что проверено при подготовке

Проверены JavaScript, связность файлов, относительные пути, подлинность и читаемость трёх JPEG, точные тексты поздравлений, сохранность первого экрана и программные сценарии открытия/переходов/возврата/увеличения фото. Раскладка имеет отдельные правила для мобильных, планшетов и компьютеров.

Браузерный предпросмотр в среде выполнения недоступен. Поэтому визуальная проверка ширин 375/390/430/768/1440 px, консоль реального браузера и проверка опубликованной страницы в инкогнито не подтверждены. Публичная публикация не выполнена: подключение GitHub не предоставило репозитории и операции создания репозитория/настройки Pages. Эти проверки нужно завершить после загрузки.
